# BANK_V1 - 项目归档与架构演进说明

> 本文档是历史归档与演进说明，不承载当前执行计划。当前执行约束以根目录 `plan.md` 为准。

## 1. 项目愿景与初始 Ideal

项目最初目标是构建一个基于 HIRD（Hierarchical Intent-Native Risk Defense）架构的手机银行全链路风控系统，借助 Agent 协作与微观行为识别，实现从“规则拦截”向“意图识别”的跨越。

初始理想分为四层：

- 感知集成层（HIRD-H）：多模态数据采集与上下文压缩。
- 认知决策层（HIRD-C/R）：基于 Agent 的语义理解与风险推理。
- 治理控制层（HIRD-G）：确定性规则与金融级安全控制。
- 业务执行层（HIRD-E）：结果展示与业务动作执行。

## 2. V1 到 V3-alpha 的演进结果

在 V3-alpha 阶段，项目已经形成一套更偏工程落地的结构：

- FastAPI 后端承接预检、质询、确认转账及相关接口。
- RiskEngine 负责风险评分与决策组合。
- RiskKnowledgeBase 提供知识召回与向量语义匹配能力。
- AgentService 负责 LLM 调度与二次质询逻辑。
- PiiMasker 提供脱敏与隐私保护能力。

这一阶段的价值在于：先验证决策质量和链路稳定性，而不是优先引入更复杂的编排框架。

## 3. V1 遗留问题

V1 及其过渡实现暴露出以下问题：

1. Agent 职责重叠，分类与语义识别边界不清。
2. 决策链路黑盒，中间推理过程难以审计与复核。
3. 治理层动作不完整，例如取消交易语义未显式建模。
4. 单一 Prompt 难以随风险场景扩展而持续维护。

## 4. 本轮架构调整依据

当前文档治理与架构调整，主要针对上述问题进行收敛：

- 用三类 Agent 固定职责边界，替代单体式语义风险混合判断。
- 保持“Agent 负责分析，治理层负责裁决”的硬边界。
- 将 Trace 作为独立审计流，而不是主决策链路的一部分。
- 在正式引入图式编排框架前，先稳定手写调度、接口契约与状态字段。

## 5. 归档结论

- V1 的 Ideal 方向仍然成立。
- 当前阶段不是否定 Ideal，而是采用更务实的实施顺序。
- 后续若进入 V4，才重新评估是否以 LangGraph/LangChain 承接完整的图式编排。
