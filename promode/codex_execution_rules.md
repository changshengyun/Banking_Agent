# Codex Execution Rules

> 本文件汇总了当前项目中已经明确的执行规则。  
> 每次执行前先阅读本文件。

## 1. 计划与执行

- 先形成计划，再按 `plan.md` 执行。
- `plan.md` 是当前唯一活动执行计划。
- 代码实现、验证结果和版本状态变化后，要同步相关文档。

## 2. 多 Agent 协作

- substantial task 默认按多 Agent 协作思路拆分。
- 必须有一个验收 Agent 负责总验收。
- 验收任务重时，可以继续拆分子验收 Agent 并行处理。
- 多 Agent 的写入范围不能重叠，避免同一文件并发改写。

## 3. 沟通方式

- 能从仓库和代码里自证的问题，不反复向用户提问。
- 发现重大歧义、且仓库无法回答时，再最小化提问。
- 中间进度要直接、简洁、面向事实。

## 4. 实现约束

- 不碰 Flutter SDK，只改项目代码。
- 保持现有对外接口语义稳定，除非用户明确要求变更。
- 先稳主链路，再做框架迁移或大规模重构。
- 对现代实体、最新信息和行业基线，优先查证，不靠记忆写死。

## 5. 文档同步

- 每次实现后至少同步：
  - `plan.md`
  - `MVP.md`
  - `README.md`
- 若本轮涉及架构、公式或数据流变化，还要同步：
  - `nowthink.md`
  - `math.md`
- 同步后需检查 `plan/MVP/README` 的阶段、版本、关键指标是否一致。

## 6. Git 与提交

- Git 操作使用非交互命令。
- 不回滚用户未明确要求回滚的改动。
- 常规迭代可按需提交；大版本完成时（按 `plan.md` 验收门槛）必须执行 `git commit + git push`。
- 大版本默认推送当前工作分支，除非用户明确指定其它分支策略。

## 7. 当前项目固定策略

- `precheck` 保持知识库 + 规则引擎热路径。
- Agent 主要用于 `secondary-check`。
- `precheck all-Agent` 只允许 shadow mode 评估。
- Trace 作为独立审计链路，不介入主裁决。
